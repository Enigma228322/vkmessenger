# VKM / VK — нативный VK Мессенджер


Новый UI по скриншотам VK подключён частично: тёмная лента без пузырей, группы авторов, единое меню с быстрыми реакциями и правая панель информации. В настройках доступны светлая тема и прежний вид с пузырями. Подробный статус и оставшиеся работы — в [журнале реализации](docs/ui-implementation.md).
C++20, Qt 6.8+, Qt Quick; основная платформа — macOS Apple Silicon. Версия 0.2.0 переводит основные действия из универсальных форм API в обычный интерфейс мессенджера и добавляет постоянное локальное хранилище.

Полный план находится в [PLAN.md](PLAN.md), состояние пользовательских сценариев и внешние зависимости — в [docs/parity.md](docs/parity.md), история заметных изменений — в [CHANGELOG.md](CHANGELOG.md). Полный паритет с официальным web-клиентом ещё не достигнут.

## Запуск и вход

```sh
open -n ./build/VK.app
```

Для обычного входа приложение должно быть собрано с зарегистрированным VK app ID и разрешением на Messages API. Настройки задаёт разработчик при сборке; пользователь нажимает «Войти через VK ID» и подтверждает вход в системном браузере. Автоматический loopback callback должен быть разрешён для выбранного приложения VK.

Для HTTPS redirect реализован возврат через `vkm://auth/callback`: подтвердите открытие VK в браузере или нажмите «Вернуться в приложение». Ручная вставка HTTPS callback доступна в окне входа как резервный способ. Код обменивается на токен внутри приложения с PKCE и проверкой state; исходный HTTPS redirect сохраняется, повторный callback не повторяет обмен. На сервере `153-51-114-47.sslip.io` 28 октября 2026 установлена новая страница автоматического возврата; конфигурация и откат описаны в [инструкции](docs/automatic-login-return.md). Доступ к Messages API ещё не подтверждён живым входом.

Вход через access_token доступен на стартовом экране и в настройках во всех сборках. Если app ID не настроен, можно использовать access_token или демоверсию. Уже сохранённая пользовательская сессия восстанавливается независимо от наличия app ID в новой сборке. Успешный VK ID login сам по себе не доказывает доступ к личным сообщениям или getDiff.

Добавлен отдельный экспериментальный вход «Войти через VK API» на стартовом экране и в настройках. Он использует OAuth `response_type=token`, `scope=messages` и собственный app ID сборки (по умолчанию `54850913`). После подтверждения нужно вставить полный адрес `https://oauth.vk.com/blank.html#…` в окно приложения. Проверяются `state`, срок действия и аккаунт через `users.get`; токен сохраняется только в системном хранилище паролей. Этот способ не использует сервер возврата и не обновляет токен через VK ID: после истечения срока нужен новый вход.

Доступность этого OAuth для `54850913` не подтверждена. 28 октября 2026 запросы без авторизованной браузерной сессии к OAuth с `blank.html` и зарегистрированным HTTPS redirect вернули HTTP 401, `invalid_request`, `Security Error`. Если браузер показывает такую ошибку, токен не выдан. Кнопка позволяет проверить способ в своей браузерной сессии, но не предоставляет приложению дополнительных прав на Messages API.

После обмена callback на токен приложение отдельно проверяет доступ к сообщениям. Если web-метод `messages.getDiff` недоступен, клиент переключается на публичные `messages.getConversations`, `messages.getHistory` и Long Poll v3. Если VK запрещает и публичное чтение, в том числе из-за типа профиля, сессия сохраняется, запросы сообщений останавливаются и показывается ограничение с названием метода и числовым кодом; повторять вставку callback не требуется. Доступ должен быть предоставлен на стороне VK.

Сессия хранится в macOS Keychain или Linux Secret Service (GNOME Keyring). Токены не записываются в SQLite, настройки или логи. При выходе очередь и черновики сохраняются на диске и восстанавливаются после входа в тот же аккаунт. Деморежим сохраняет реальную сессию и использует отдельный медиакэш.

Для разработчиков предусмотрена отдельная сборка с `VKM_ENABLE_API_INSPECTOR=ON`: в ней доступны настройка VK ID и инспектор API. Вход через access_token доступен и в обычной сборке.

## Пользовательские действия

Основные сценарии используют обычные окна и кнопки:

- Ответ над редактором, редактирование текста с сохранением вложений, пересылка через выбор получателей и комментарий.
- Выбор нескольких сообщений, удаление с подтверждением и доступным вариантом «у всех», важность, закрепление, реакции и список отреагировавших.
- Создание и переименование беседы, выбор участников, просмотр списка, роли, ограничение письма на час, приглашение и выход.
- Архив, закрепление диалогов, прочитанность, важность и включение/выключение уведомлений на стороне VK.
- Поиск сообщений и людей с задержкой при наборе и защитой от устаревших ответов; переключение между текущей перепиской и всеми сообщениями, переход из результата в контекст. Без сети доступен поиск по сохранённым сообщениям; при наличии FTS5 используется полнотекстовый индекс SQLite.
- Каталог активных наборов и избранных стикеров; отправка нажатием, добавление в избранное правой кнопкой мыши.
- Просмотр фотографий с масштабированием и панорамированием; встроенное воспроизведение аудио и предоставленных VK видеопотоков, перемотка, скорость и громкость.
- Папки диалогов: выбор, создание, переименование, состав переписок, порядок и удаление; восстановление без сети и обновление через Long Poll.
- Тихая отправка через меню рядом с кнопкой отправки, включая восстановление очереди после перезапуска.
- Запись голосового сообщения в Ogg/Opus, прослушивание перед добавлением в черновик; загрузка файлов с прогрессом, отменой и повтором.
- Ссылки на сообщения вида `vkm://chat/77?message=3`, которые открываются этим приложением.
- Системные уведомления macOS о новых входящих: включение в «Настройки → Уведомления», звук, скрытие текста и переход к сообщению по нажатию. При первом включении нужен доступ macOS.

Доступность серверных операций зависит от прав аккаунта и беседы. Изменения чатов и медиа ещё требуют проверки с подходящей тестовой сессией VK. Если сервер отдаёт только HTML-плеер видео без доступного потока, есть отдельная кнопка открытия в VK.

Для геопозиции, опросов, всех бизнес-сценариев и некоторых дополнительных типов вложений полные пользовательские сценарии ещё не реализованы. Звонки пока не реализованы. Уведомления работают, пока приложение запущено, включая фон и свёрнутое окно; доставка после полного завершения приложения через APNs не реализована. Активная открытая переписка, отключённые уведомления беседы, тихие и прочитанные сообщения не создают баннеров.

## Кэш и работа без сети

Данные разделены по аккаунтам. SQLite обслуживается отдельным потоком; сетевые запросы и подготовка файлов не блокируют интерфейс.

- `AppLocalDataLocation/storage/history.sqlite`: диалоги, профили, папки, каталог реакций, история, проверенные интервалы, поисковый индекс и версия синхронизации.
- `AppLocalDataLocation/storage/personal.sqlite`: черновики, ответы, очередь исходящих и состояние загрузок. Эта база не очищается вместе с кэшем.
- `AppLocalDataLocation/storage/uploads/`: подготовленные копии вложений; после подготовки оригинал можно переместить или удалить. Копии удаляются при подтверждённом переносе готового вложения в исходящее сообщение или удалении из черновика.
- `CacheLocation/media/`: фотографии, изображения реакций и стикеры; каталог каждого аккаунта изолирован.

Дисковый медиакэш по умолчанию ограничен 1 ГиБ; в настройках доступны 256 МиБ, 1/5/10 ГиБ. Старые файлы вытесняются по давности обращения. Отдельная автоматически кэшируемая загрузка ограничена 128 МиБ; большие медиа можно воспроизводить по сети и сохранять в выбранный пользователем файл.

Для истории установлен предел 100 тысяч сообщений и 512 МиБ сериализованного содержимого на все аккаунты. Это предел содержимого: индексы SQLite, свободные страницы и WAL требуют дополнительного места. В активной ленте удерживается ограниченное окно. До шести недавно открытых переписок сохраняют в памяти по 200 сообщений для немедленного повторного открытия; остальные оставляют только последнее сообщение, полная сохранённая история остаётся на диске. Кэш недавних переписок очищается при выходе и полном сбросе синхронизации.

«Настройки → Данные и память» показывает размеры и позволяет очистить историю или медиакэш. Очистка сохраняет черновики, очереди и пользовательские загрузки в Finder.

При восстановлении сохранённой сессии доступны кэшированные переписки даже без сети. Исходящее сначала записывается на диск, затем появляется в ленте и отправляется. После обрыва сохраняется прежний `random_id`, а неопределённая доставка отображается отдельно. HTTP-ответ и Long Poll echo согласуются в любом порядке; подтверждение обновляет существующий элемент ленты.

Подготовленные загрузки восстанавливаются после перезапуска; неподготовленный файл должен оставаться доступен до завершения копирования. Поддерживается повтор загрузки целиком, а не продолжение с произвольного байта на сервере VK.

## Синхронизация и интерфейс

Для совместимых сессий используются `messages.getDiff`, `getDiffContent` и Long Poll v21: POST, `version=21`, `mode=682`. Состояние diff и `server_version` сохраняются одной транзакцией. Транспортный `ts` хранится отдельно. Старые ответы истории не могут перезаписать diff, находящийся на стадии сохранения в БД.

При недоступном getDiff используется публичный API: постраничный список диалогов, история и `messages.getLongPollServer` с Long Poll v3. Полный полученный список заменяется транзакционно с сохранением кэшированной истории; версия diff не придумывается. Для перехода к CMID сначала определяется глобальный ID через `messages.getByConversationMessageId`. Этот режим не обеспечивает все расширенные сценарии web-протокола; серверные права по-прежнему обязательны.

API обслуживается общей очередью с интервалом 350 мс и ограниченным приоритетом пользовательских действий. Long Poll использует отдельный транспорт. Существующие проверки Int64, страниц diff, invalidate и поколений запросов сохранены.

Добавлены мягкое появление исходящих, переходы диалогов и отклик кнопок. Уменьшение движения учитывает настройку приложения и macOS. Анимации стикеров останавливаются вне экрана и в неактивном окне. Системная светлая/тёмная тема поддержана базовыми поверхностями; полный визуальный аудит и измерение 60/120 Гц остаются задачами плана.

## Сборка

Нужны Xcode Command Line Tools, CMake, Qt Quick, Quick Controls, Network, Concurrent, SQL, Multimedia, SVG и Qt Test. rlottie и libopus 1.6.1 закреплены на конкретных версиях; архивы проверяются SHA-256. При первой конфигурации нужны доступ к исходникам или подготовленные локальные зависимости.

```sh
cmake -S . -B build \
  -DCMAKE_PREFIX_PATH="$HOME/Qt/6.11.1/macos" \
  -DCMAKE_BUILD_TYPE=Release \
  -DVKM_VK_APP_ID=54850913 \
  -DVKM_VK_REDIRECT_URI=https://153-51-114-47.sslip.io/callback
cmake --build build --parallel
QT_QPA_PLATFORM=offscreen ctest --test-dir build --output-on-failure
```

По умолчанию используется VK ID приложение `VK Messenger App`, ID `54850913`, redirect `https://153-51-114-47.sslip.io/callback`. Эти публичные параметры можно переопределить при сборке. При необходимости разрешённые приложению scopes передаются через `VKM_VK_SCOPE`. Никакие секретные ключи не следует включать в бинарник.

Для сборки без скачивания libopus можно передать `-DVKM_OPUS_LIBRARY=/absolute/path/libopus.0.dylib` и `-DVKM_OPUS_LICENSE=/absolute/path/COPYING`. Библиотека должна соответствовать архитектуре приложения. macOS bundle получает собственную копию динамической библиотеки; установка кодека у пользователя не требуется.

Для диагностического интерфейса добавьте `-DVKM_ENABLE_API_INSPECTOR=ON`. Production-сборка по умолчанию использует `OFF`.

## Самопроверка и упаковка macOS

На macOS обычная сборка `cmake --build build --parallel` автоматически обновляет Qt и плагины внутри `VK.app` и подписывает пакет. Это необходимо после повторной линковки: свежий бинарник и ранее упакованные плагины иначе могут загрузить разные копии Qt и аварийно завершиться при запуске. CTest также проверяет самопроверку упакованного приложения (`app-bundle-self-check`). Для отдельной повторной упаковки:

```sh
cmake -DAPP_BUNDLE="$PWD/build/VK.app" \
  -DQT_ROOT="$HOME/Qt/6.11.1/macos" -P cmake/DeployMac.cmake
QT_QPA_PLATFORM=offscreen build/VK.app/Contents/MacOS/VK --self-check
```

`--self-check` использует временное хранилище и не читает, не сохраняет и не удаляет сессию Keychain. Проверяет загрузку QML, SQLite, GIF, декодирование WebP и SVG (из файла без расширения, как в медиакэше), иконку и реальное кодирование Ogg/Opus во временный файл. Запускайте после DeployMac, чтобы Qt и плагины внутри bundle соответствовали свежему бинарнику. Можно добавить `--screenshot=/absolute/path/preview.png`.

Перед релизом нужна и проверка с настоящей графической подсистемой macOS: `QT_QPA_PLATFORM=cocoa build/VK.app/Contents/MacOS/VK --self-check`. Она кратко открывает демоокно; требуется графическая сессия. Проверка `offscreen` не проверяет инициализацию Cocoa и нативной иконки Dock.

DeployMac включает Cocoa, offscreen, TLS, JPEG/GIF/SVG, SQLite и мультимедийные плагины с их зависимостями, подписывает bundle ad-hoc и проверяет подпись. Для внешнего распространения остаются Developer ID и notarization.

```sh
sh scripts/package-macos-release.sh dist/VK-0.2.0-macOS-arm64.zip
```

Скрипт проверяет подпись и запуск через Cocoa у собранного и распакованного приложения, целостность ZIP и создаёт файл SHA-256. Итоговый архив заменяется только после успешных проверок.

## Проверки

Двенадцать наборов тестов (включая JavaScript-проверки при наличии Node.js) проверяют протокол и авторизацию, интеграцию моделей и QML, Long Poll, метаданные developer API, передачи файлов, Lottie, SQLite и медиакэш. Заметные изменения интерфейса, производительности и поведения добавляются в `CHANGELOG.md` в том же патче. Новые проверки включают:

- перезапуск без сети с историей, черновиком и исходящим сообщением;
- повтор отправки с прежним `random_id` и сохранением тихого режима;
- операции папок, отказ VK без изменения локального списка, фильтры, восстановление без сети и обновления Long Poll;
- кодирование PCM в Ogg/Opus и декодирование результата, контроль длительности, заголовков, CRC, неполного кадра и отмены;
- перенос голосовой записи в постоянную очередь без оставшегося исходного файла;
- получение Long Poll echo раньше HTTP-ответа, сохранение идентичности карточки и отсутствие повторного создания outbox;
- старый ответ истории в момент асинхронного commit diff;
- очистку кэша без удаления пользовательских данных, изоляцию аккаунтов и локальный поиск;
- объединение загрузок одного ресурса и вытеснение по лимиту медиакэша;
- восстановление подготовленного вложения после удаления исходного файла;
- передачу правильных CMID и сохранение вложений при редактировании через пользовательский диалог;
- границы времени и галочек, короткие/многострочные сообщения, геометрию ленты и сохранение позиции при подгрузке;
- объединение переопределений каталога реакций по ID, фактическую загрузку PNG/WebP/SVG в чипы, picker и быстрое меню, WebP-стикер.

Тесты используют подставной API и отдельные каталоги. Живые операции VK, реальная запись микрофона, визуальная плавность на Metal и полный паритет с web требуют отдельных проверок из PLAN.md.

На macOS статические изображения WebP читаются встроенным Qt-плагином через системный ImageIO. Это работает и для файлов медиакэша без расширения. Анимация WebP этим декодером не поддерживается; для анимированных стикеров используются Lottie/GIF.

## Ubuntu 24.04 LTS (Intel/AMD x86_64)

Собрана и проверена версия `.deb` с Qt 6.11.1 и QML-модулями. [Успешная проверка Ubuntu](https://github.com/Enigma228322/vkmessenger/actions/runs/43190265270). Сборка и проверки выполняются workflow `.github/workflows/ubuntu-24.04.yml`; готовый пакет и SHA-256 появляются в артефакте `ubuntu-24.04-amd64` после успешного завершения.

Установка скачанного пакета:

```sh
sudo apt install ./vkmessenger_0.2.0_ubuntu24.04_amd64.deb
```

Запуск — из меню приложений или `/opt/vkm/bin/VK`. Сессия сохраняется через Secret Service; в стандартной Ubuntu его предоставляет GNOME Keyring. Системные уведомления на Linux пока не реализованы.

Для повторной сборки установите зависимости из workflow и официальный Qt SDK, затем выполните:

```sh
QT_ROOT_DIR=/path/to/Qt/6.11.1/gcc_64 sh scripts/build-ubuntu-package.sh
```

Скрипт запускает CTest, упаковывает приложение, проверяет запуск из распакованного пакета через offscreen и X11/Xvfb и записывает контрольную сумму в `dist/ubuntu`. CI дополнительно проверяет установку в чистой Ubuntu 24.04 и хранение сессии в изолированном GNOME Keyring.
