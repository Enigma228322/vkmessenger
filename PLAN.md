# VKM: план полноценного нативного VK Мессенджера

Дата: 24 октября 2026. Статус: реализация начата; полный паритет ещё не достигнут.

## Приоритет интерфейса по скриншотам 24 октября 2026

Подробный рабочий план: [Паритет интерфейса VK Мессенджера](docs/ui-parity-plan.md). Основание — два скриншота пользователя в 15:40:37 и 15:40:47 и доступные исходники web-проекта. Прямой осмотр вкладки Chrome не выполнен из-за ограничения инструмента; свойства, не видимые на снимках, не считаются проверенными в браузере.

Основной визуальный эталон — **тёмная лента без пузырей**, группировка сообщений по автору, компактные время/галочки, панель информации справа и единая композиция «быстрые реакции + меню сообщения». Перекраска текущих пузырей и добавление новых независимых модальных окон не закрывают этот объём.

Порядок следующих работ:

1. **U0:** обезличенные эталонные состояния, реестр возможностей/прав и исходные замеры.
2. **U1:** общие токены, иконки, оболочка, список и основной flat-вариант истории с сохранением якоря.
3. **U2:** привязанное к сообщению меню с быстрыми реакциями, копированием текста, пересылкой и выбором.
4. **U3:** правая панель профиля: участники, приглашения, настройки и разделы вложений.
5. **U4:** согласованный редактор, поиск, папки, медиа и стикеры с полноценными состояниями.
6. **U5:** оставшиеся сценарии каналов/сообществ, управления, заявок, ботов и системной интеграции.
7. **U6:** совместимые звонки, разрешённая живая сверка, измерение производительности и окончательная приёмка. Исследование транспорта звонков начинается уже в U0.

U0 и U4–U6 остаются открытыми; U1–U3 реализованы частично. Точный объём изменений и оставшиеся условия: [текущее выполнение UI](docs/ui-implementation.md). Полный паритет не подтверждён. Переиспользовать уже работающие API-клиент, SQLite, outbox, загрузки, Lottie и WebP; переносить экраны небольшими вертикальными изменениями. Вход через access_token сохранить по отдельному требованию пользователя. Исходные M0–M8 ниже остаются общим техническим планом; U0–U6 уточняют порядок и критерии пользовательского интерфейса.

Первая приёмка: на обезличенных данных воспроизведены обе композиции снимков; короткие и длинные сообщения, время/галочки, реакции и контекстное меню не пересекаются; профиль и загрузки сохраняют позицию/фокус; ошибки не теряют черновики. Полный паритет требует отдельной проверки всего реестра, включая состояния, не показанные на снимках.

## Текущее выполнение — 0.2.0

Реализованы отдельный `VkApiClient`, слой пользовательских действий, SQLite worker, постоянные черновики/outbox, восстановление подготовленных загрузок, общий медиакэш с лимитом, локальный поиск, пользовательские окна основных действий, просмотрщик и запись голоса через libopus в отдельном потоке. Добавлены папки с выбором переписок, синхронизацией и локальным восстановлением, тихая отправка и постоянный каталог реакций. Добавлены переходы, Reduce Motion, стабильная идентичность исходящего сообщения и deep links. Подробное состояние и проверки — в [docs/parity.md](docs/parity.md).

M1–M5 выполнены частично: транспорт синхронизации ещё не выделен полностью, модели остаются общими, а продвинутые пользовательские сценарии и измерения производительности не завершены. M6–M8 остаются открытыми. В сборке настроен VK ID app `54850913` (`VK Messenger App`) с redirect `https://153-51-114-47.sslip.io/callback`; живой вход и доступ приложения к Messages API ещё нужно подтвердить; в найденной копии web-проекта звонки представлены интерфейсом и заглушками, а не готовым медиатранспортом.

Ниже сохранены исходные требования и критерии приёмки. Их наличие в плане не означает выполнение; локальные тесты не заменяют живую проверку VK.

## 1. Цель и критерий завершения

Сделать на базе существующего C++20 / Qt Quick клиента полноценный повседневный мессенджер для macOS: привычные сценарии web-приложения VK, приятная анимация, быстрый локальный отклик, постоянный кэш и работа с сохранёнными данными без сети.

Пользователь выбирает людей, сообщения, файлы и действия. Он не вводит `peer_id`, `cmid`, ID стикера, `random_id`, JSON, параметры OAuth или названия API-методов. Для пересылки открывается выбор получателя, для редактирования — редактор сообщения, для участников — список людей с доступными действиями.

Полнота определяется проверенными пользовательскими сценариями web-мессенджера, а не числом методов в `Methods::catalog()`. Реализация формы вызова API не считается готовой функцией. Критерии каждого сценария: нормальный экран, успешное выполнение, обработка отказа, корректное состояние после перезапуска и синхронизация с другим клиентом.

Полный паритет остаётся целью всего плана. Промежуточная версия для ежедневной переписки — отдельный этап, а не завершение задачи. Недоступный серверный контракт фиксируется как блокер соответствующей функции; открытие web-страницы или скрытие кнопки не превращает её в реализованную нативную функцию.

## 2. Исходное состояние перед реализацией 0.2.0

Основание этой оценки — просмотр исходников, QML, CMake и тестов в текущем каталоге. В предыдущем локальном прогоне проходили шесть тестовых наборов. Эти тесты используют подставной API; полного сравнения с авторизованным актуальным web-приложением пока нет.

- `src/Messenger.cpp` / `.h`: авторизация, очередь API, getDiff, применение событий, история, отправка, действия и модели объединены в одном классе. Это работающая основа, которую нужно разделять постепенно.
- `src/LongPoll.cpp`, `LongPollEvent.h`: транспорт v21, восстановление соединения и классификация событий. Сохранить существующие проверки курсоров, поколений запросов и отмены.
- `ItemModel` в `Messenger.h`: общий список `QVariantMap` с ролью `item`. Поиск линейный; согласование списка может выполнять повторные линейные проходы. Данные истории и версии синхронизации находятся в памяти.
- `qml/Main.qml`: основная навигация, лента, редактор и многочисленные диалоги в одном большом файле. Отступы и восстановление позиции уже проверяются, но компонентная система интерфейса и согласованная система анимации отсутствуют.
- `qml/MethodBrowser.qml`, `ResultView.qml`: универсальный интерфейс параметров и результатов API. Через него проходят создание чата, поиск, пересылка, редактирование, удаление, участники, архив, уведомления и другие обычные действия.
- `src/Methods.cpp`: каталог и кодирование методов полезны как материал для адаптеров и диагностических инструментов. Они не должны оставаться пользовательским интерфейсом.
- `src/Transfers.cpp`: последовательная очередь загрузки файлов, сохранение вложений, скачивание через `QSaveFile`. Нет полноценной постоянной модели заданий, медиатеки и восстановления загрузок после перезапуска.
- `qml/AttachmentView.qml`: фотографии и стикеры отображаются; многие другие вложения представлены названием и внешней ссылкой. Встроенных аудио-/видеоплееров и записи с микрофона нет.
- `src/LottieSticker.cpp`: rlottie, фоновые разбор/рендеринг, пауза, JSON/gzip, HTTPS-кэш на 64 МиБ. Это частный кэш стикеров, а не общий кэш приложения.
- `src/OAuth.cpp`, `Keychain.cpp`: PKCE и хранение сессии уже есть, но основной вход требует токена, а альтернативный — настройки приложения и redirect URI. Доступ к сообщениям через готовый пользовательский вход нужно подтвердить отдельно.
- Черновики находятся в JS-объекте `drafts`; отправка блокируется общим `m_sending`; постоянного outbox и мгновенного локального сообщения до ответа сервера нет.
- `BotKeyboard.qml`: часть кнопок работает непосредственно, местоположение ведёт в форму API. Звонки распознаются как события; медиатранспорт не реализован.
- `cmake/DeployMac.cmake`: упаковка Qt, плагинов и ad-hoc подпись. При добавлении SQLite и мультимедиа потребуется изменить состав bundle; сейчас скрипт удаляет каталог SQL-драйверов.

**Результат:** полный реестр с источниками и зависимостями. Неизвестная возможность не считается отсутствующей. Заблокированная функция остаётся открытой задачей полного паритета, с конкретной причиной и необходимым следующим шагом.

Проверки с изменением сообщений выполняются в выделенных тестовых переписках. Захваты протокола и тестовые фикстуры не содержат токенов и личной переписки.

## 4. Целевая архитектура и постепенный перенос

Разделять код по работающим вертикальным сценариям. Сначала извлечь сервис и подключить к нему существующий экран, затем заменить экран; после каждого шага приложение собирается и сохраняет поведение getDiff/v21.

Предлагаемые границы:

```text
src/
  app/          AppController, SessionController, навигация и жизненный цикл
  domain/       Message, Conversation, Peer, Attachment, Draft, capabilities
  api/          VkApiClient, RequestScheduler, типизированные адаптеры и ошибки
  sync/         SyncEngine, LongPollTransport, EventDecoder, согласование версий
  storage/      DatabaseWorker, репозитории, миграции, CacheManager
  messaging/    MessageActions, OutboxService, DraftService, ConversationActions
  models/       ConversationsModel, MessagesModel, MembersModel, SearchModel
  media/        TransferQueue, MediaRepository, PlaybackService, Recorder
  stickers/     StickerCatalog, StickerCache, существующий LottieSticker
  calls/        CallService, сигнализация и отдельный медиабэкенд
  platform/     Keychain, уведомления, ссылки, разрешения, интеграция macOS
qml/
  shell/        окно, список диалогов, навигация, боковые панели
  chat/         лента, пузырь, редактор, ответ, редактирование, выбор сообщений
  dialogs/      получатели, создание чата, подтверждение удаления, приглашения
  media/        просмотрщик, плееры, запись и очередь файлов
  settings/     аккаунт, уведомления, внешний вид, кэш
  components/   темы, типографика, кнопки, состояния, motion-токены
```

- C++ отвечает за состояние, права, идентификаторы, кэш, сетевые команды и согласование. QML отвечает за отображение и взаимодействие; формат API не распространяется по экранным компонентам.
- Команды выражают намерение: `editMessage`, `forwardMessages`, `setReaction`, `setMutedUntil`, `createChat`. Идентификаторы и необязательные параметры вычисляются внутри адаптера.
- Результат операции связан с конкретным сообщением, диалогом или заданием. Убрать общие на всё приложение `operationResult` и `operationBusy` из обычных сценариев.
- Ввести отдельные роли моделей и точечные уведомления. Изменение прочтения или реакции не пересоздаёт всю карточку сообщения. Добавить индексы по ключам и корректные перемещения диалогов.
- Идентичность сообщения: аккаунт + peer + CMID; глобальный message ID хранится отдельно. Для локального исходящего сообщения — постоянный local ID и последующее сопоставление. Int64 не сравнивается через JS `Number`.
- Сетевой I/O остаётся асинхронным. БД, декодирование медиа и тяжёлая обработка работают вне GUI-потока. Изменения `QAbstractItemModel` применяются в потоке модели.
- `RequestScheduler` учитывает ограничения VK, приоритет видимого чата и отправки, отмену устаревшего поиска, объединение одинаковых чтений, backoff и повтор после допустимых ошибок. Приоритет не означает обход лимитов API или голодание фоновой синхронизации.
- Ввести `Capabilities`: доступные операции зависят от аккаунта, беседы, сообщения и серверных ограничений. Скрывать неприменимые действия, объяснять временные ограничения, повторно проверять право при выполнении.
- Инспектор API оставить только в сборке разработчика, например `VKM_ENABLE_API_INSPECTOR=OFF` по умолчанию. У production-интерфейса не должно быть зависимости от `MethodBrowser` и страницы сырых результатов.

## 5. Постоянный кэш, офлайн и сохранность действий

Кэш — обязательная часть архитектуры и первый этап после выделения сервисов. Чтение начинается с локальных данных, сетевое обновление происходит в фоне и точечно меняет модели.

### 5.1. Три уровня хранения

- **SQLite:** диалоги, профили, сообщения, вложения и их метаданные, реакции, участники, границы прочтения, проверенные интервалы истории и состояние синхронизации. Добавить Qt SQL; проверить наличие FTS5 в поставляемом SQLite перед выбором локального полнотекстового индекса.
- **Дисковый медиакэш:** аватары, превью, фотографии, стикеры, обложки, загруженные для просмотра аудио/видео. У каждого файла есть запись индекса с размером, владельцем, датой доступа и версией ресурса.
- **Ограниченный кэш RAM:** активное окно истории, соседние страницы, изображения нужного размера и небольшой набор кадров стикеров. Объём RAM не растёт вместе со всей историей аккаунта.

Постоянные данные размещать через `QStandardPaths::AppLocalDataLocation`, заменяемые медиа — через `CacheLocation`. Конкретные пути скрыты за сервисом хранения. Ключи всех уровней включают аккаунт; отрицательные ID сообществ и разные пространства идентификаторов не смешиваются.

### 5.2. Что нельзя удалять как обычный кэш

- Черновики, содержимое локальных исходящих, стабильные `random_id`, очередь команд и файлы ещё не отправленных вложений — пользовательские данные в отдельном постоянном хранилище.
- Перед сетевой отправкой команда и её идентификатор сохраняются на диск. Файлы очереди либо копируются в управляемое постоянное место, либо имеют подтверждённый долговременный доступ; исчезновение исходного файла не должно бесшумно уничтожать отправку.
- «Очистить кэш» не удаляет черновики, очередь отправки и файлы, которые пользователь отдельно сохранил в Downloads/Finder.
- Выход из аккаунта и удаление его локальных данных — отдельный сценарий. При наличии неотправленных сообщений пользователь видит последствия и может сохранить их или отменить выход. Деморежим изолирован и не вызывает удаление реальной сессии, как сейчас делает `startDemo()` через `logout()`.

- [ ] Хранить проверенные интервалы истории: отсутствие сообщения в неполном кэше не равно удалению. При очистке старых страниц одновременно корректировать интервалы и поисковый индекс.
- [ ] Разбирать и применять события с проверкой поколения сессии. Ответ старого аккаунта или старого запроса не попадает в новый экран/БД.
- [ ] Медиаключ строить из сущности, варианта размера и версии, а не только временного CDN URL. При истечении URL обновлять метаданные; использовать ETag/Last-Modified, если сервер их предоставляет.
- [ ] Записывать файлы атомарно, удалять незавершённые временные файлы после сбоя, восстанавливать индекс. Общий сервис объединяет конкурентные загрузки одного ресурса.
- [ ] SQLite обслуживает выделенный worker со своим соединением; предусмотреть транзакции, WAL, checkpoint и миграции. При переполненном диске отправка не получает ложный статус «надёжно сохранена».
- [ ] Повреждение заменяемого кэша допускает его перестроение. Для outbox и черновиков нужен отдельный путь восстановления с сохранением исходного файла, а не автоматическое удаление всей базы.

### 5.4. Политика размеров и экран настроек

Начальные настраиваемые бюджеты, которые нужно подтвердить измерениями:

- Общий дисковый медиакэш по умолчанию 1 ГиБ; варианты 256 МиБ, 1/5/10 ГиБ, статистика отдельно по аккаунтам. Автозагрузка видео выключена, автозагрузка фотографий зависит от настроек.
- Для заменяемой базы истории — отдельный бюджет, стартово 512 МиБ. Хранить недавние открытые окна, подгружать по потребности, вытеснять старые данные порциями. Защищённые локальные данные учитывать отдельно и явно показывать их размер.
- Декодированные изображения и кадры в RAM — стартовый общий бюджет 128 МиБ. Ограничить размер текстур и число одновременно проигрываемых стикеров; хранение всех кадров всех анимаций запрещено.
- Вытеснение LRU с защитой используемых файлов. TTL метаданных назначается по типу; изменения сообщений определяются синхронизацией, а не только TTL.
- Экран «Настройки → Данные и память»: размеры категорий, лимиты, автозагрузка, очистка медиа/истории, размер защищённых данных, прогресс и результат очистки.
- Токены остаются в Keychain. База и файлы недоступны другим пользователям ОС; логи не содержат текста переписки и токенов. Шифрование самой локальной истории — отдельное явно проверяемое решение, не заявлять его наличия только из-за использования Keychain.

**Приёмка кэша:** после перезапуска без интернета открываются сохранённые диалоги и история; доступны сохранённые вложения; явно показано отсутствие сети. Новые исходящие остаются в очереди и отправляются после восстановления доступа. Поиск обозначает, что найдено только в локально сохранённой истории. Очистка медиа не теряет черновики и исходящие; размер кэша возвращается в заданный бюджет; повторная синхронизация не создаёт дубликаты.

## 6. Пользовательские сценарии вместо параметров API

Для всех разделов нужны состояния loading/empty/offline/error, локализованный текст, клавиатурное управление, отмена и повтор. Ошибка привязана к месту действия; сообщения вроде «параметр cmid не указан» в обычном интерфейсе недопустимы.

### 6.1. Вход, аккаунт и навигация

- [ ] Экран «Войти через VK», штатное подтверждение в браузере и автоматический возврат. Конфигурация приложения поставляется разработчиком; пользователь не заполняет client ID, scope и callback.
- [ ] Восстановление/обновление сессии, повторный вход без потери локальных черновиков, понятные состояния отказа и дополнительных проверок VK. QR-вход — только после подтверждения доступного контракта.
- [ ] Список диалогов с аватарами, последним сообщением, автором, непрочитанными, упоминаниями, черновиками, активностью и статусом отправки.
- [ ] Закреплённые, архив, непрочитанные, избранное/важное; папки и порядок согласно подтверждённому web-эталону. Локальную настройку не выдавать за синхронизируемую серверную папку.
- [ ] «Новое сообщение» через выбор контакта/поиск человека, «Новая беседа» через выбор нескольких людей и название. Карточка человека и переход в профиль.
- [ ] Назад/вперёд, сохранение позиции каждого чата, deep links к диалогу/сообщению, адаптивная боковая панель. Несколько аккаунтов — отдельные сессии, базы, очереди и счётчики, если включено в согласованный объём эталона.

### 6.2. Лента и редактор

- [ ] Группировка по автору и времени, разделители дат и непрочитанных, локальное время, системные события беседы, признаки изменения и удаления.
- [ ] Текст, ссылки, безопасное отображение упоминаний и поддерживаемого форматирования, выделение и копирование. Корректная работа emoji, многострочного текста и длинных слов.
- [ ] Автоматическая подгрузка истории при приближении к краю, заполнение разрывов, переход к конкретному сообщению и возврат к прежней позиции. Сохранение якоря при изменении размеров медиа, реакций и окна.
- [ ] Read receipt только для действительно видимого сообщения в активном окне; высокое сообщение должно становиться прочитанным при осмысленном просмотре, даже если целиком не помещается в viewport.
- [ ] Локальное исходящее появляется сразу. Состояния «в очереди», «загрузка вложений», «отправляется», «отправлено», «прочитано», «ошибка» не подменяют серверное подтверждение.
- [ ] Outbox сохраняет порядок зависимых действий по диалогу, позволяет отправлять в разных чатах, повторяет с прежним `random_id` и согласует HTTP-ответ с Long Poll независимо от порядка прихода.
- [ ] Неоднозначный результат отправки имеет отдельное состояние и проверку; не обещать exactly-once для операций без серверной идемпотентности.
- [ ] Редактор с растущей высотой до разумного лимита, Enter/Shift+Enter, IME, вставкой фото/файлов, drag-and-drop, emoji, упоминаниями, черновиком текста/вложений/ответа по диалогу.
- [ ] Отложенные, тихие и исчезающие сообщения, если подтверждены эталоном: собственные элементы управления и серверные состояния. Локальный таймер при закрытом приложении не считается серверной отложенной отправкой.

### 6.3. Действия с сообщениями

- [ ] Ответ — панель над редактором с автором, превью и переходом к оригиналу.
- [ ] Редактирование — режим редактора с сохранением вложений, отменой и проверкой актуальных ограничений сервера.
- [ ] Пересылка одного/нескольких сообщений — выбор одного/нескольких получателей, превью, комментарий и подтверждение; никаких JSON и ручных ID.
- [ ] Выбор нескольких сообщений мышью/клавиатурой и панель групповых действий. Частичный успех групповой операции отображается для конкретных сообщений.
- [ ] Удаление — обычный диалог с доступными вариантами «у меня»/«у всех». Восстановление предлагается только при подтверждённой возможности; не обещать отмену необратимого удаления.
- [ ] Реакции — быстрый выбор, изображения/анимации, агрегированные счётчики, моя реакция, снятие, список людей по нажатию. Прочтение реакций выполняется автоматически по соответствующему сценарию просмотра.
- [ ] Закрепление/открепление, просмотр закреплённых, важность, копирование текста/ссылки, переход к ответам/оригиналам согласно эталону.
- [ ] Оптимистичное изменение там, где оно обратимо; откат учитывает более новые серверные изменения, а не восстанавливает устаревшую копию всего сообщения.

### 6.4. Поиск и информация о чате

- [ ] Глобальный поиск и поиск в текущей переписке с debounce, отменой устаревших запросов, подсветкой совпадений и пагинацией.
- [ ] Фильтры по дате, собеседнику/автору и типу вложения в пределах подтверждённых возможностей. Локальные результаты показывать быстро, затем дополнять серверными без дублей.
- [ ] Открытие результата в контексте с краткой подсветкой сообщения и возвратом в поиск.
- [ ] Панель информации: название, фото, описание, участники, уведомления, закреплённые, общие фотографии/видео/аудио/файлы/ссылки, поиск.
- [ ] Создание/переименование беседы, смена фото с обрезкой, добавление людей через контактный picker, роли, ограничения и удаление через меню участника.
- [ ] Приглашения: просмотр/копирование/обновление ссылки; вступление с превью чата; выход с подтверждением. Роли и исключение из беседы обновляются без перезапуска.
- [ ] Архивирование, закрепление, прочитанность, удаление переписки и mute на срок — непосредственные действия с понятным результатом.
- [ ] Запросы на переписку, запрет сообщений, блокировка, жалоба и ограничения приватности — по реестру эталона и доступным правам.

### 6.5. Медиа, файлы, стикеры

- [ ] Общая очередь файлов с превью, прогрессом по каждому заданию, отменой/повтором и устойчивой привязкой к черновику. Повтор после перезапуска поддерживается; продолжение с байтового смещения — только если это позволяет сервер.
- [ ] Фото и альбомы в сообщениях, просмотрщик с zoom/pan, перелистыванием, сохранением, копированием и переходом к исходному сообщению.
- [ ] Встроенный видеоплеер: воспроизведение, пауза, перемотка, громкость, полный экран, выбор качества при доступных потоках. HTML `player` URL не передавать в `QMediaPlayer` как видеофайл.
- [ ] Голосовые: waveform, позиция, скорость, очередь воспроизведения, признак прослушивания; расшифровка, если её предоставляет VK.
- [ ] Запись микрофона с разрешением ОС, отменой, прослушиванием до отправки, обработкой смены устройства. Видеосообщения — после проверки формата и upload-контракта.
- [ ] Музыка/аудио, документы, ссылки, записи, контакты, геопозиция, опросы и остальные вложения из реестра — специальные карточки и действия. Неизвестный тип имеет аккуратное превью и понятный доступ к оригиналу, без сырого JSON.
- [ ] GIF/анимации, подарки и действия с опросами исследовать отдельными сценариями: получение, просмотр, выбор/создание и отправка в той мере, в которой они доступны в web-эталоне. Наличие общей карточки вложения не закрывает интерактивный сценарий.
- [ ] Picker emoji/стикеров: наборы, недавние, избранные, поиск/подсказки при наличии данных, предпросмотр, отправка нажатием. Наборы и право использования получаются от VK, а не из вручную введённого ID.
- [ ] Анимированные стикеры используют существующий rlottie, общий кэш и лимит нагрузки; светлые/тёмные варианты, статическое превью, pause по видимости и Reduce Motion.
- [ ] Подключить Qt Multimedia; проверить необходимые кодеки, аппаратное декодирование и поставляемые плагины на целевой macOS. Решение о дополнительном медиабэкенде принимать по реальным форматам и измерениям.

### 6.6. Сообщества, боты и внешние сервисы

- [ ] Inline/обычные клавиатуры, one-time-состояния, карточки и карусели, callback с индикатором выполнения и результатом у кнопки.
- [ ] Отправка местоположения через карту/выбор места и разрешение пользователя, а не поля `lat`/`long`.
- [ ] Настройки разрешения сообщений сообщества и доступные действия подписки/отписки — обычные элементы интерфейса.
- [ ] Для поддерживаемой работы от имени сообщества — отдельный контекст, права операторов, отвеченные/важные диалоги и соответствующие сценарии. Групповой токен не подменяет пользовательскую сессию.
- [ ] Mini Apps, VK Pay, покупки наборов и другие сервисы требуют отдельной проверки интеграции. Допустимый переход во внешний сервис явно отражается в реестре; весь мессенджер не переносится в WebView ради этих исключений.
- [ ] Конструирование произвольного JSON клавиатуры, отправка служебных callback-ответов и просмотр сырых событий остаются инструментами разработчика, если их нет в пользовательском web-сценарии.

### 6.7. Звонки

- [ ] После успешного P0-прототипа: входящий/исходящий личный аудио- и видеозвонок, отказ, занятость, пропущенный, завершение с обеих сторон.
- [ ] Групповой звонок, участники, приглашение/присоединение, mute, камера, выбор микрофона/динамика/камеры и переключение во время звонка.
- [ ] Демонстрация экрана/окна с разрешениями macOS, просмотр демонстрации, компактное окно звонка, восстановление при смене сети.
- [ ] Отдельная state machine жизненного цикла, обработка эха, сетевых разрывов и отзыва разрешения. Системные звонки/ссылки отображаются в истории согласованно.
- [ ] Выбрать совместимый с VK медиабэкенд после проверки сигнализации, транспорта и условий доступного SDK. Qt Multimedia обеспечивает захват/воспроизведение, но сам по себе не реализует протокол звонков VK.

Наличие методов `calls.*` или события Long Poll типа Call не является готовой поддержкой звонков. Если совместимый доступ не подтверждён, весь этот раздел сохраняет статус блокера полного паритета.

### 6.8. Настройки и macOS

- [ ] Светлая/тёмная/системная тема, масштаб текста, плотность, фон переписки и другие подтверждённые настройки оформления.
- [ ] Уведомления macOS, Dock badge, mute по беседе, предпросмотр текста и конфиденциальность, переход к сообщению; быстрый ответ, если поддержан выбранной интеграцией.
- [ ] Системные сочетания клавиш, меню, Finder drag-and-drop, clipboard, deep links, сохранение размеров окна, корректные sleep/wake и сетевое переподключение.
- [ ] Разрешения микрофона/камеры/экрана запрашиваются в момент соответствующего действия. Отказ обрабатывается внутри сценария.
- [ ] VoiceOver, доступные названия, порядок фокуса, видимый focus ring, контраст, увеличение шрифта и управление без мыши.
- [ ] Поведение при закрытом окне и завершённом процессе определено явно. Уведомления при полностью завершённом приложении требуют отдельного подтверждённого механизма доставки; один Long Poll этого не обеспечивает.
- [ ] Настройки кэша, загрузок, воспроизведения, анимации и сессии доступны без технических параметров.

## 7. Визуальная система и приятная анимация

Сначала единые компоненты, затем анимация их состояний. Цель — мягкий понятный отклик без задержки действий и скачков ленты.

- Общие токены цвета, радиусов, отступов, высот и типографики; отдельно состояния hover, press, focus, disabled, selected и error. Проверять длинные имена и русские подписи.
- `Motion.qml`: быстрый отклик 80–120 мс, меню/tooltip 120–180 мс, панели 180–240 мс, появление сообщения 120–180 мс. Значения — исходные параметры дизайна, уточняются на реальном устройстве.
- Основные эффекты: opacity и небольшой translate/scale. Сдержанный easing; без постоянного «пружинения» текста и длинных анимаций, блокирующих ввод.
- Новое сообщение в конце мягко появляется, локальное отправляемое превращается в подтверждённое без удаления/повторной вставки. Подгруженные старые страницы не проигрывают анимацию каждого элемента.
- Реакция кратко увеличивается, счётчик меняется без сдвига соседних строк; открытие picker сохраняет фокус и положение сообщения.
- Панели информации, поиск, выбор получателя и медиа имеют согласованные переходы. Прерывание и обратный переход работают даже в середине анимации.
- История сохраняет якорь, когда меняется высота. Не ставить безусловный `Behavior on height` на все элементы виртуализированной ленты; внешнюю геометрию согласовывать с прокруткой.
- Автопрокрутка разрешена, когда пользователь находится у конца, либо явно нажал переход. При чтении старой истории новые сообщения дают счётчик и не перехватывают позицию.
- Typing, запись голоса, прогресс отправки и skeleton показывают конкретное состояние и не мерцают при каждом diff.
- Reduce Motion следует настройке ОС и может быть включён в приложении: убрать перемещения/масштабирование и автоматические декоративные циклы, сохранить доступные статические состояния и ручное воспроизведение.
- Невидимое, свёрнутое и неактивное окно не тратит ресурсы на декоративные циклы. Ограничить число фоновых задач rlottie; при профилированном узком месте рассмотреть передачу готовых текстур через scene graph.

**Приёмка:** запись основных сценариев на 60 Гц и, при наличии, 120 Гц; быстрые повторные открытия/закрытия, переключение тем и Reduce Motion, обновление ленты во время анимации. Offscreen-тесты проверяют состояние и геометрию, но не доказывают плавность GPU-рендеринга.

## 8. Производительность: измерять преимущество над web

C++ сам по себе не ускоряет ответы серверов VK. Выигрыш должен обеспечиваться локальным кэшем, быстрым локальным отображением действия, ограниченными моделями и отсутствием тяжёлой работы в GUI-потоке.

Зафиксировать эталонную машину, Release-сборку, версию macOS, частоту экрана и набор данных. Начальные цели для Apple Silicon уровня M1 / 8 ГБ, подлежащие подтверждению в P0:

- Холодный запуск с существующим кэшем до рабочего интерфейса — p95 ≤ 1 с; сетевой refresh измеряется отдельно.
- Переключение на сохранённый диалог до первого полезного кадра — p95 ≤ 100 мс.
- Нажатие отправки до локального пузыря — p95 ≤ 50 мс; сохранность команды на диске проверяется отдельно от серверной задержки.
- Появление локальных результатов поиска после debounce — p95 ≤ 150 мс на 100 тысячах сохранённых сообщений.
- Плавная прокрутка на 60 Гц: p95 времени кадра ≤ 16,7 мс, не более 1% пропущенных кадров в фиксированном 30-секундном сценарии. Для 120 Гц отдельная цель 8,3 мс при соответствующей поддержке устройства.
- Проверочный объём: 10 тысяч диалогов и 100 тысяч сообщений на диске; в UI только ограниченное окно истории. Базовая цель памяти для текстовой переписки ≤ 250 МиБ; медиарежим измеряется отдельно с заданным лимитом RAM-кэша.
- Простой без активных медиа — в среднем < 1% одного CPU-ядра за минуту; в неактивном окне нет постоянных декоративных render loop.

Профилировать QML Profiler, Instruments и временные метки стадий запроса/БД/модели/кадра. Сравнить VKM и web на одинаковых аккаунтах, машине, сети, данных и степени прогрева кэша; отдельно показать холодные и тёплые сценарии. Итоговые значения фиксировать в отчёте, не объявлять ускорение без измерений.

## 10. Проверка и единый Definition of Done

Сохранить существующие `ProtocolTest`, `LongPollTest`, `MethodsTest`, `MessengerTest`, `TransfersTest`, `StickerTest`, постепенно распределяя проверки по новым модулям. Тест открытия каждой формы API оставить только для developer-инспектора; он не является критерием готовности продукта.

- **Контракты:** реальные обезличенные формы ответов, большие Int64, повторные/переставленные события, failed=1/2/3/4, invalidate, страницы diff, отказ доступа, потерянный HTTP-ответ после успешной операции.
- **Хранилище:** миграции, атомарность данных и версии, crash до/после commit, disk full, повреждение кэша, восстановление индекса, лимиты, изоляция аккаунтов и очистка.
- **Исходящие:** перезапуск до отправки, во время загрузки и после серверного приёма; событие раньше HTTP-ответа; повтор без дубликата; частичный отказ пересылки; изменение/отмена локальной команды.
- **UI:** каждый сценарий реестра проходит через обычные кнопки и picker. Проверить узкое/широкое окно, Retina, длинные тексты, emoji, пересылки, огромные медиа, клавиатуру, IME, VoiceOver и Reduce Motion.
- **Геометрия:** сохранение якоря при prepend, edit/delete/reaction, загрузке изображения и resize; отсутствие скачка при чтении старой истории; открытие результата поиска в контексте.
- **Медиа:** недоступный/истёкший URL, ошибочный формат, отмена, смена чата, разрешений и устройства, sleep/wake, много анимированных стикеров при ограниченной памяти.
- **Живой VK:** вход, двусторонняя переписка с web, чтение/редактирование/удаление/реакции, права, файлы, боты и звонки на выделенных аккаунтах. Успех подставного API не заменяет эти проверки.
- **Производительность:** воспроизводимые Release-прогоны и графики времени кадра; отсутствие роста памяти в длительном сценарии; сравнение с web по разделу 8.
- **Выпуск:** чистая установка, автономные зависимости, обновление с сохранением БД/очереди, подпись, проверка архива и явно указанная архитектура сборки.

Функция считается завершённой только когда её UI не раскрывает технические параметры, состояние переживает необходимые перезапуски, ошибки и права обработаны, синхронизация с другим клиентом подтверждена и тест сценария включён в регрессию.
