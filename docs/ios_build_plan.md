# iOS-сборка VKM для iPhone и TestFlight

## Цель и принятые решения

Перенести существующее приложение C++/Qt Quick на iPhone, сохранив все реализованные пользовательские функции, и подготовить подписанную сборку для TestFlight.

- Использовать общее C++-ядро и QML, без переписывания на Swift.
- Целевая платформа — iPhone, iOS 17+. Qt 6.11 поддерживает эту версию ОС. Документация Qt (https://doc.qt.io/qt-6.11/ios.html).
- Первая доставка — внутренний TestFlight; затем внешние тестировщики.
- Сохранить macOS-сборку и её поведение.
- План и команды сборки оформить в docs/ios-build-plan.md.

Под «всеми функциями» понимаются уже реализованные возможности проекта. Звонки, push-уведомления и другие отсутствующие функции в этот перенос не входят.

## 1. Подготовить окружение и подпись

- Установить полный Xcode и выбрать его через xcode-select: сейчас выбран каталог Command Line Tools.
- Использовать Xcode 26 или новее с iOS SDK 26 или новее — это действующее требование загрузки в App Store Connect. Минимальная версия устройства при этом остаётся iOS 17. Требования Apple (https://developer.apple.com/news/upcoming-requirements/).
- Установить Qt 6.11.1 для iOS и соответствующие host tools; зафиксировать версии инструментов в инструкции.
- Подготовить отдельные каталоги сборки для симулятора и физического устройства.
- Получить доступ к Apple Developer Program и App Store Connect: наличие доступа пока не подтверждено.
- Зарегистрировать iOS Bundle ID dev.reforged.messenger.ios, настроить команду разработки и автоматическую подпись Xcode. Team ID передавать параметром конфигурации.
- Создать карточку приложения в App Store Connect. Сертификаты и приватные ключи не хранить в репозитории.

## 2. Перенести сборку и платформенный код

В CMakeLists.txt разделить общие Apple-зависимости, macOS и iOS.

- Исключить AppKit из iOS; реализовать определение Reduce Motion через UIKit.
- Добавить отдельный iOS Info.plist: идентификатор, версии, схема возврата, описание доступа к микрофону, поддерживаемые ориентации.
- Добавить AppIcon и экран запуска; убрать macOS-пути вида Contents/Resources из iOS-упаковки.
- Собирать Opus и rlottie из закреплённых исходников под целевую платформу. Не использовать macOS-библиотеки в iOS-сборке.
- Проверить WebP-плагин, SVG, SQLite, Qt Multimedia и регистрацию статических QML/Qt-плагинов.
- Подключить iOS к реализации Security Keychain: сейчас она включена только для macOS.
- Использовать sandbox-каталоги приложения для базы, черновиков, загрузок и кэша; исключить macOS-миграцию путей на iOS.
- Добавить воспроизводимые конфигурации CMake для simulator/device и команду создания Release-архива. Обычный desktop ctest не считать запуском тестов на iPhone.

## 3. Адаптировать вход и пользовательские сценарии

Авторизация

- Сохранить существующий HTTPS redirect VK ID.
- Добавить отдельную схему vkm-ios://auth/callback.
- Передавать выбор платформы в state вместе с криптографически случайной частью; приложение проверяет полное исходное значение.
- На HTTPS-странице выбирать только фиксированные разрешённые адреса возврата для macOS/iOS. Не принимать произвольный redirect из параметров.
- Открывать VK ID в системном браузере; на странице callback делать попытку возврата и показывать кнопку «Вернуться в приложение».
- Передавать callback в OAuth через обработчик URL iOS/Qt. Сохранять PKCE, проверку state и исходный HTTPS redirect_uri при обмене токена.
- После завершения процесса приложения предлагать новый вход: verifier не сохранять на сервере.
- Проверить права текущего VK app ID на реальные операции Messages API отдельно от успешного входа.

Интерфейс

- Убрать минимальную ширину 780 пикселей для iOS.
- На телефоне использовать последовательные экраны: список чатов → переписка → информация о чате.
- Адаптировать настройки, поиск, вложения и диалоги под ширину экрана, safe areas и экранную клавиатуру.
- Заменить действия, доступные только через hover, правую кнопку или клавиатурные сочетания, на видимые кнопки и долгое нажатие.
- Сохранить переписки, папки, реакции, пересылку, редактирование, поиск, черновики, очередь отправки и управление кэшем.

Файлы, медиа и жизненный цикл

- Получать вложения через системный выбор файлов; импортировать выбранные данные в sandbox перед постановкой в очередь.
- Проверить изображения, видео, аудио, стикеры и запись Ogg/Opus на реальном iPhone.
- Обработать отказ в доступе к микрофону, прерывание записи и смену аудиоустройства.
- При уходе в фон сохранять состояние и завершать запись; после возвращения восстанавливать соединение и синхронизацию.
- Не рассчитывать на непрерывный Long Poll в фоне. Неопределённые результаты отправки согласовывать с сервером без создания дублей.

## 4. Проверить функциональность и подготовить TestFlight

Автоматические и ручные проверки

- Прогнать существующие тесты ядра и регрессию macOS.
- Добавить проверки маршрутизации callback, неверного/просроченного state, повторного возврата и отмены входа.
- Проверить запуск QML и основные экраны на небольшом и большом iPhone в симуляторе.
- На физическом устройстве проверить вход без копирования ссылки, сохранение сессии, сообщения, вложения, голосовые, стикеры и воспроизведение.
- Проверить offline, смену сети, фон/возврат, принудительное завершение, восстановление черновиков и очереди.
- Проверить обновление установленной сборки без потери данных.
- Составить проверочный список всех реализованных возможностей по README; каждый пункт должен иметь результат на iOS.

Упаковка и распространение

- Собрать подписанный .xcarchive, сохранить dSYM и журнал сборки.
- Проверить privacy manifest приложения и зависимостей, описания разрешений, сведения об обработке данных и экспортном шифровании.
- Включить уведомления о сторонних лицензиях и проверить условия распространения используемой сборки Qt.
- Выполнить Validate App и загрузить архив через Xcode Organizer.
- Настроить внутреннюю группу TestFlight, описание тестирования и контакт для обратной связи.
- После внутренней проверки подготовить внешнюю группу и информацию для Beta App Review. Первая внешняя сборка проходит проверку Apple. Порядок TestFlight (https://developer.apple.com/help/app-store-connect/test-a-beta-version/testflight-overview).

## Критерий готовности

Сборка устанавливается на iPhone через TestFlight, вход завершается без ручного переноса URL, все реализованные функции проекта доступны с сенсорного интерфейса, сессия и локальные данные переживают перезапуск и обновление. Проверки macOS остаются успешными.

Обязательные внешние условия: доступ к Apple Developer Program, управление HTTPS-страницей callback и подтверждённые права VK API. Подготовку кода и симуляторной сборки можно выполнять до получения этих доступов; публикация и полноценная проверка входа зависят от них.
