# Состояние сценариев VKM 0.2.0

Дата: 24 октября 2026. Проверка выполнена по локальным C++/QML, подставному API и исходникам web-проекта `/Users/v.safin/reforged`. Авторизованный официальный web-клиент и живая тестовая сессия VK пока не проверены. «Реализовано локально» означает код и локальную проверку, а не подтверждённый паритет с VK.

## Реализовано локально

- **SYNC-01 — getDiff и Long Poll v21.** Транспорт, страницы, отдельные курсоры, отмена, диапазоны изменений/удалений и восстановление. В 0.2.0 diff и его версия фиксируются SQLite-транзакцией; добавлена защита от истории, пришедшей во время commit. Источники: `src/LongPoll.cpp`, `src/Messenger.cpp`, `src/storage/LocalStore.cpp`. Проверки: `LongPollTest`, `MessengerTest::staleHistoryCannotOverwriteCommittingDiff`.
- **CACHE-01 — история после перезапуска.** Сначала SQLite, затем обновление VK; отдельные аккаунты, ограниченное окно RAM, очистка истории. Проверки: `StorageTest`, `cacheAndOutgoingSurviveOfflineRestart`.
- **CACHE-02 — медиакэш.** Диск, объединение запросов, атомарные файлы, бюджет и вытеснение; изображения, реакции и Lottie используют общую службу. Проверки: `MediaCacheTest`. Временные CDN URL пока являются частью ключа; смена URL может создать новую копию ресурса.
- **CACHE-03 — локальный поиск.** FTS5 при наличии, резервный поиск в worker, пометка локальных результатов и переход в сохранённый контекст. Проверка полнотекстового поиска и удаления индекса: `StorageTest`. Метрика p95 на 100 тысячах сообщений пока не измерена.
- **DRAFT-01 — черновики.** Постоянное хранение текста и ответа; подготовленные/загруженные файлы сохраняются отдельным состоянием. Переключение диалога не переносит чужой черновик. Очистка кэша не удаляет protected database.
- **SEND-01 — постоянные исходящие.** Сохранение до отправки, локальный пузырь, состояния очереди/отправки/неопределённой доставки/ошибки, повтор с прежним `random_id`. Проверки: `cacheAndOutgoingSurviveOfflineRestart`, `longPollEchoBeforeHttpKeepsIdentityAndCannotRecreateOutbox`.
- **MSG-01 — ответ и редактирование.** Панель ответа и текстовый редактор; вложения сохраняются, CMID вычисляется из контекста. Проверка: `nativeMessageActionsUseContextAndPreserveAttachments`.
- **MSG-02 — пересылка.** Выбор одного/нескольких получателей, комментарий, очередь отправки; исходный и получательский черновики сохраняются. Проверяется правильный `forward` без ручного JSON.
- **MSG-03 — выбор/удаление/важность/закрепление.** Контекстные меню и панель выбранных сообщений, подтверждение удаления, доступный вариант «у всех». Частичный отказ удаления показывается пользователю. Полная матрица серверных прав и сроков ещё требует проверки.
- **MSG-04 — реакции.** Каталог изображений, установка/снятие, список людей. Переопределения объединяются по ID с основным каталогом; picker учитывает `reaction_ids`. В сообщениях отображаются компактные чипы, своя реакция выделена; нажатие устанавливает/снимает реакцию, правая кнопка открывает список людей. Статические WebP декодируются нативным ImageIO-плагином и читаются из медиакэша без расширения. Каталог обновляется после суток, поскольку URL VK могут истекать. Проверка `reactionCatalogAndImagesRenderInMessagesAndPicker` проверяет реальную готовность PNG/WebP в ленте и picker, включая WebP-стикер. Прочтение реакций не вынесено в ручную форму. Полная автоматическая обработка всех состояний реакций ещё требует доработки и живой проверки.
- **SEARCH-01 — серверный поиск.** В отдельном окне; локальные результаты появляются раньше сетевого ответа, результаты открываются в истории. Доступен выбор поиска в текущем диалоге. Изменение запроса сразу делает прежние ответы неактуальными; переключение области запускает новый поиск, пустое поле очищает результаты, закрытие окна прекращает применение ответов. Онлайн-пагинация не подмешивает локальные страницы; повторы объединяются по peer + CMID с сохранением порядка. Проверки: `searchInvalidatesImmediatelyAndRestartsOnScopeChange`, `searchPaginationKeepsServerOrderAndDeduplicatesByPeer`. Фильтры по датам и автору пока отсутствуют.
- **PEER-01 — выбор получателей.** Сохранённые диалоги и поиск людей через `users.search`; без ввода ID. Нужна живая проверка прав выбранного приложения и сценария нового контакта.
- **CHAT-01 — беседы.** Создание, название, фото через загрузку, список участников с пагинацией, приглашение, вступление и выход. Источники контрактов: `UserChangedChatMember.ts`, `UserChangedConvo.ts` и `IApi.ts` web-проекта.
- **CHAT-02 — роли и ограничения.** `admin`/`member`; ограничение письма `ro` на час и снятие `rw`, обработка `failed_member_ids`. Передача владения и произвольные сроки пока не реализованы.
- **CHAT-03 — организация диалогов.** Архивирование, закрепление, важность, отметки прочтения и mute/unmute вызываются непосредственно из меню. Папки и их редактор описаны отдельно в FOLDER-01.
- **MEDIA-01 — фотографии.** Кэш, просмотрщик, zoom/pan, сохранение файла. Перелистывание общего альбома и обрезка фото чата пока отсутствуют.
- **MEDIA-02 — воспроизведение.** Аудио/голосовые и доступные прямые видеопотоки в Qt Multimedia; пауза, позиция, скорость, громкость. HTML `player` не подаётся как медиафайл; для видео предусмотрено отдельное открытие в VK. Полный экран, очередь аудио, waveform, отметки прослушивания и выбор качества ещё не реализованы.
- **MEDIA-03 — запись голоса.** Разрешение микрофона, Ogg/Opus, остановка, прослушивание, добавление в черновик. Захват PCM через `QAudioSource`, кодирование libopus 1.6.1 и Ogg в отдельном потоке, атомарное завершение файла, перенос в постоянную очередь без лишнего оригинала. `VoiceCodecTest` проверяет декодирование результата, CRC, pre-skip и длительность; `--self-check` кодирует временный файл. Реальная запись и отправка требуют отдельной проверки с микрофоном и VK.
- **UPLOAD-01 — восстановление файлов.** Копирование в защищённый каталог вне GUI-потока, сериализация очереди, повтор целиком после перезапуска. Проверка: `TransfersTest::stagedUploadSurvivesRestartWithoutOriginalFile`. До окончания подготовки исходный файл должен быть доступен. Возобновление с байтового смещения не заявлено.
- **STICKER-01 — обычные и анимированные стикеры.** Picker активных наборов/избранного, отправка нажатием, добавление в избранное правой кнопкой; rlottie JSON/gzip и пауза по видимости. Поиск по ключевым словам, управление наборами и полный магазин пока отсутствуют.
- **BOT-01 — кнопки ботов.** Текст и payload проходят через постоянную очередь; callback — через C++-действие и сопоставление event ID. Ссылки и приложения открываются явно. Выбор геопозиции на карте, карусели и все состояния одноразовой клавиатуры пока не завершены.
- **UI-01 — движение и геометрия.** Переходы диалогов, отклик кнопок и появление локальных сообщений; сохранение идентичности при серверном подтверждении, сохранение позиции, учёт Reduce Motion приложения/macOS. Ширина пузыря вычисляется через `FontMetrics`, текст и время — с метриками их фактического шрифта. Время и галочки занимают отдельный футер; реакции расположены в горизонтальном потоке с переносом. Есть проверки границ футера, однострочных коротких сообщений, узкого/широкого окна и якоря; запись плавности на 60/120 Гц пока не проведена.
- **MAC-01 — ссылки на сообщения.** Копирование `vkm://chat/...`, зарегистрированная схема bundle и обработка `QFileOpenEvent`; открытие откладывается до восстановления сессии.

- **FOLDER-01 — папки.** Список и выбор папки, создание/редактирование с выбором переписок, переименование, перестановка и подтверждение удаления. Встроенные папки читаются с фильтрами `included_lists_info`; явные исключения приоритетнее включений. Каталог сохраняется в SQLite и переживает полный diff и запуск без сети. События 501–509/10501–10509 обновляют папки одним запросом на пакет без пересинхронизации всей истории. Проверки: `MessengerTest::foldersUsePeerPickerContractsAndSurviveOfflineRestart`, `StorageTest::catalogsSurviveFullDiffAndRemainAccountScoped`. Источники: `src/browser/hooks/useCreateFolder.ts`, `src/core/model/Folder.ts`, `src/data/store/EngineBatchReceived.ts` исходного web-проекта. Редактирование правил динамических списков, счётчики папок и настройка рекомендованных папок пока не завершены.
- **SEND-02 — тихая отправка.** Пункт «Отправить без звука» рядом с кнопкой отправки. `silent=1` хранится вместе с outbox и прежним `random_id`; перезапуск и повтор покрывает `MessengerTest::cacheAndOutgoingSurviveOfflineRestart`. Контракт подтверждён `src/data/store/UserHitSend.ts` web-проекта. Живая проверка уведомления получателя остаётся открытой.
- **CACHE-03 — каталоги и аватары.** Каталоги папок и изображений реакций изолированы по аккаунтам и сохранены в SQLite; аватары используют общий ограниченный медиакэш. Это позволяет восстановить оформление сохранённой переписки без повторного получения каталога реакций.

## Внешние зависимости и блокеры

### AUTH-01 — готовый вход через VK

PKCE и callback реализованы. В production-конфигурации app ID, зарегистрированный redirect и scopes задаются при сборке; технические поля пользователя скрыты. Для завершения нужны зарегистрированное приложение с доступом к Messages/getDiff и проверка настоящего входа. В текущей сборке app ID пустой; доступны вход через access_token, деморежим и восстановление ранее сохранённой сессии. Вход через access_token открыт на стартовом экране и в настройках независимо от developer-инспектора.

Подтверждение обычного VK ID login не заменяет проверку доступа к Messages API. Секретный ключ не должен встраиваться в клиент. Живой токен не нужен в тексте чата.

### CALL-01 — совместимые звонки

`/Users/v.safin/reforged/src/data/env/ICalls.ts` содержит интерфейс окружения. В `src/browser/renderer.tsx` обнаружены `alert('Calling...')`, `alert('Joining...')` и другие заглушки. В этой копии web-проекта нет готовой реализации медиатранспорта для переноса.

Для нативных звонков остаётся подтвердить доступный совместимый SDK/контракт сигнализации и медиатранспорта, затем реализовать state machine, устройства, видео, группы и демонстрацию экрана. Наличие `calls.*`, Qt Multimedia или события Call не закрывает этот сценарий. Открытие внешнего приложения не считается нативной реализацией.

### LIVE-01 — проверка с официальным клиентом

Нет настроенной выделенной тестовой сессии и подтверждённого набора прав для живой проверки. Все изменяющие операции должны проверяться в тестовых диалогах. Текущие tests/fixtures не подтверждают серверные ограничения, поведение новых контрактов или полное соответствие web.

## Кодирование голоса

Использован публичный стабильный ABI libopus; зависимость закреплена на 1.6.1 и может собираться из исходников или подключаться явно для офлайн-сборки. [API кодека](https://opus-codec.org/docs/opus_api-1.6/) и [RFC 7845](https://www.rfc-editor.org/rfc/rfc7845.html) определяют формат пакетов, pre-skip и завершающее обрезание. Поддерживается микрофон с форматом 48 кГц, mono, Int16; неподдерживаемый формат устройства отображается как ошибка. Запись ограничена 20 минутами. Системный Qt encoder Ogg/Opus в установленном SDK отсутствует, поэтому он больше не используется для записи.

## Конфигурация VK ID

В обычную сборку добавлены публичные параметры приложения `VK Messenger App`: ID `54850913`, redirect `https://153-51-114-47.sslip.io/callback`. Для HTTPS возврата доступно окно вставки полного callback URL; оно не требует API-инспектора. Проверяются state и точное соответствие redirect, токен обменивается локально с PKCE. Access_token остаётся альтернативным способом входа. На сервере `153.51.114.47` пользователь настроил HTTPS-страницу возврата; базовый домен — `153-51-114-47.sslip.io`. Независимая сетевая проверка из текущей среды недоступна. Автоматический возврат в приложение и реальные права Messages API не проверены. Подставные тесты и self-check подтверждают конфигурацию/UI, но не успешную авторизацию на сервере VK.

Ссылка `/authorize` дополнена `app_id`, `sdk_type=vkid`, `v=2.6.1` по [формированию URL в официальном VK ID SDK](https://github.com/VKCOM/vkid-web-sdk/blob/master/src/utils/url/url.ts). Это параметры совместимости страницы авторизации; клиент остаётся нативным. Тест проверяет согласованность `app_id`/`client_id`, redirect и PKCE, а также отсутствие verifier/секрета в URL. Устранение ошибки загрузки на стороне VK ещё требует повторного живого входа.
